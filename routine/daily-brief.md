# Daily brief procedure (runs 5:00 a.m. Mountain, in a cloud session)

You are producing today's Merchant Growth Lab brief. Work from the repo root. Be efficient: tokens are spent reading page text, not viewing images. Prefer plain scripts to model work wherever a script exists.

## What "a specimen" means now
A specimen is a **site survey**, not a two-click flow. The capture script follows the site's own top-level nav: home, pricing, products, developer/platform docs, solutions, customers, company, resources, then the signup path. Each page's text is saved to `data/captures/<id>/page-N.txt`. Your job is to answer, from that text: what do they sell, what does it cost, what is the technical platform, how do they present the company, and how does the pitch hold up. Every fact needs a verbatim quote that the validator checks.

## Budget rules (hard)
- The owner wants this run to stay well under their usage allocation. Default is **1 featured (full survey) + 2 batch (lite survey)**. Drop to **0 batch** if `data/cost-log.json` shows the previous run had retries, errors, or `partial: true`.
- Featured: `node capture/capture.mjs <id>` (about 14 pages). Read it with `node scripts/digest.mjs <id> 1200`; open specific pages with the third argument (e.g. `node scripts/digest.mjs <id> 3500 2` for the pricing page). View at most **4 images** (home, pricing, one product page, signup).
- Batch: `node capture/capture.mjs <id> --lite` (about 6 pages). Digest at 800 chars per page. View at most **1 image**. Dossier sections are optional for lite surveys; scores you cannot evidence stay `null`; `confidence: "low"`.
- Stop expanding and publish what you have if: more than **8 images** viewed in total, more than **2 capture retries**, or any rate-limit or usage warning. Mark the cost entry `partial: true`.
- At most **one** WebSearch (standard mode) for news, at most **3** news candidates added.

## Steps
1. **Setup.** `npm ci && npm --prefix site ci && npx playwright install --with-deps chromium` (if `--with-deps` fails, retry without it). If Playwright cannot run at all, skip to step 8 and report the failure.
2. **Pick.** `node scripts/next-batch.mjs 2`. Output gives `featured` and `batch` ids. If `featured` is null, the queue is empty: do the news scan and stop.
3. **News scan (one search).** Search for newly launched or newly changed merchant-growth products or flows in the news from the last 48 hours (store builders, payments/checkout, POS, subscriptions, retention, marketplaces, merchant finance, AI for merchants). Add up to 3 genuinely new, publicly accessible candidates: `node scripts/add-news.mjs "<name>" "<url>" "<category>" "<flow>" "<why>"`. Record them in the brief's `newFromNews`. If a news item is clearly more important than the next queued item, you may re-run `next-batch.mjs` once so it becomes today's featured specimen.
4. **Capture.** Featured first (full), then batch ids with `--lite`. One retry maximum per id. If an id ends `blocked` or has fewer than 4 pages, say so in `blockedReason` and move on; do not work around bot checks, logins, or paywalls. Logged-out public pages only. Never create real accounts, never enter personal data, never purchase. If the home screenshot shows an open menu or a cookie wall, run `node capture/capture.mjs <id> --home-only` once.
5. **Evaluate.** For each captured id, write `data/evaluations/<id>.json` with `dossier`, `scores`, `read`, `claims`. Use `data/evaluations/stripe.json` as the exact format exemplar and `data/rubric.json` (v1.1.0, 16 dimensions) for dimensions. Then `node scripts/apply-evaluation.mjs <id>`. Rules:
   - **Dossier** (neutral facts only, no judgement): sections `positioning`, `offerings`, `pricing`, `platform`, `company`. Each fact has `text`, `step`, `type: "fact"` and a **verbatim `quote`** from that page's saved text (copy from the digest; the validator rejects quotes that are not on the page). Use `type: "inference"` with no quote only for your own inference, and say so. List what you could not find under `gaps`. Never invent prices, trial terms, or anything behind the signup form.
   - **Scores:** every non-null score needs an `evidence` string citing a `step`. `null` when the surveyed pages cannot tell. `mobile`, `states` and `a11y_basics` stay `null` unless you actually assessed them.
   - **Look for conflicts between pages** (a number, a trial term, a product name that differs). They are the most useful findings.
   - **Claims:** `text` must be quoted from the stated `step`; tag `proven | plausible | unsupported`; `evidenceStep` is where the page itself backs it up, else `null`.
   - **Read:** plain, dry, evidence-first. Numbers over adjectives. Specific to this product. Hypothesis needs statement, metric, guardrail, decision rule.
6. **Brief.** Write `data/briefs/<YYYY-MM-DD>.json` (date in America/Denver: `TZ=America/Denver date +%F`) following `data/schema/brief.schema.json`. `featured` is the featured id; `batch` the others. Headline: one specific sentence about what is notable in the featured survey (a conflict, a gap, a standout), not "X teardown". Exactly three `questionsForReader`, answerable from the pages. Include `cost: {imagesViewed, retries, batchSize, partial}`.
7. **Validate and publish.** `npm run validate` then `npm run site:build`. Both must pass. If validation fails on a quote, fix the quote against the page text; if it cannot be fixed, delete that fact. If a whole specimen cannot pass, revert it to `status: "captured"`. Append one line to `data/cost-log.json` (array; create if missing) with date, imagesViewed, retries, batchSize, partial. Then `git add -A && git commit -m "Brief <date>: <featured>" && git push origin main`. The deploy workflow publishes the site. Poll `https://mikeorme.github.io/merchant-growth-lab/briefs/<date>/` up to 6 times, 20 seconds apart, until it returns 200.
8. **Notify.** Message: "Today's Merchant Growth Lab brief: <headline>" plus the link `https://mikeorme.github.io/merchant-growth-lab/briefs/<date>/`. First try a push/app notification tool if you have one. If you do not have one or it fails, send an email with the Gmail connector (`send_message`) to the repo owner's own address, mikeorme@gmail.com, subject "Lab brief <date>: <headline>", body containing the headline, one-line summary, and the link. If the run failed, send the same way with the subject "Lab brief <date>: FAILED" and one line on why. Send exactly one notification.

## Do not
- Do not change the rubric, schemas, site code, capture script, or this file during a daily run.
- Do not edit or delete other specimens' data.
- Do not publish a specimen whose page text or screenshots show a personal email, name, or card number (re-capture or mark blocked).
